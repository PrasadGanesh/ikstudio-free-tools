W1 · Easy

Running spend per customer

For each paid order, show the customer’s running total of amount_inr ordered by order_date (and order_id as tie-break). 

SELECT
  customer_id,
  order_id,
  order_date,
  amount_inr,
  SUM(amount_inr) OVER (
    PARTITION BY customer_id
    ORDER BY order_date, order_id
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_spend
FROM orders
WHERE status = 'paid'
ORDER BY customer_id, order_date, order_id;

Why. Classic running total. Explicit ROWS frame keeps peers with the same timestamp from sharing one bucket unexpectedly.

W2 · Easy

Rank of each order inside the customer

Within each customer_id, rank paid orders by amount_inr descending. Show both RANK and DENSE_RANK. Break amount ties with earlier order_date. 

SELECT
  customer_id,
  order_id,
  amount_inr,
  order_date,
  RANK() OVER (
    PARTITION BY customer_id
    ORDER BY amount_inr DESC, order_date ASC
  ) AS rnk,
  DENSE_RANK() OVER (
    PARTITION BY customer_id
    ORDER BY amount_inr DESC, order_date ASC
  ) AS dense_rnk
FROM orders
WHERE status = 'paid';

Why. Interviewers love “what’s the difference?” — RANK leaves gaps after ties; DENSE_RANK does not. Say it out loud.

W3 · Med

Days since previous paid order

For every paid order, compute days since that customer’s previous paid order. First order for a customer should show NULL days. 

SELECT
  customer_id,
  order_id,
  order_date,
  ROUND(
    julianday(order_date) - julianday(prev_date),
    1
  ) AS days_since_prev
FROM (
  SELECT
    customer_id,
    order_id,
    order_date,
    LAG(order_date) OVER (
      PARTITION BY customer_id
      ORDER BY order_date, order_id
    ) AS prev_date
  FROM orders
  WHERE status = 'paid'
) t;

Why. Recency / inter-purchase gap = LAG on the date column. In Postgres: (order_date - prev_date).

W4 · Med

Each order’s share of the customer’s paid total

For each paid order, show amount_inr and the fraction it represents of that customer’s all-time paid total (0–1). 

SELECT
  customer_id,
  order_id,
  amount_inr,
  ROUND(
    amount_inr * 1.0
      / SUM(amount_inr) OVER (PARTITION BY customer_id),
    4
  ) AS share_of_customer_total
FROM orders
WHERE status = 'paid';

Why. Window SUM without ORDER BY is the full-partition total — handy for “% of group” without a self-join.

W5 · Med

Latest paid order per customer, then flag stale

Return only each customer’s most recent paid order. Add a flag is_stale = 1 if that order is more than 90 days before a fixed as-of date '2026-11-05'. 

SELECT
  customer_id,
  order_id,
  order_date,
  amount_inr,
  CASE
    WHEN julianday('2026-11-05') - julianday(order_date) > 90
    THEN 1 ELSE 0
  END AS is_stale
FROM (
  SELECT
    customer_id,
    order_id,
    order_date,
    amount_inr,
    ROW_NUMBER() OVER (
      PARTITION BY customer_id
      ORDER BY order_date DESC, order_id DESC
    ) AS rn
  FROM orders
  WHERE status = 'paid'
) t
WHERE rn = 1;

Why. “Latest row per group” = ROW_NUMBER + filter. Churn / reactivation screens often start here. Change the as-of date to “today” in a real warehouse.
